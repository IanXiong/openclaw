# Vibe Flow - 交互式引导入口

## 🚀 自动执行指令

**当用户通过 `@vaf_starter` 引用本文件时，AI 必须：**

1. **声明模式**：在首次响应开头输出 `🔄 [VAF Flow 模式已激活]`
2. **Banner 展示**：调用 `vibe_render_menu.py --mode banner` 脚本渲染
3. **版本检测**：执行 `vibe_check_upgrade.py`，提示升级或继续
4. **一键启动**：执行 `vibe_startup.py --json`，脚本自动完成目录校验、Git 同步、需求选择、菜单渲染

> 💡 **模式标记的作用**：
> - 后续执行阶段提示词时，AI 看到 `[VAF Flow 模式已激活]` 即知需忽略"阶段衔接"章节
> - 多轮对话后可回溯会话确认当前模式

> ⚠️ **执行要求**：
> - 直接进入流程，无需询问用户意图
> - 🚫 **必须调用脚本获取 Banner** - 确保格式一致

---

## 📋 核心规则（11 条，违反即 BLOCKER）

| # | 规则 | 约束 | 🔍 自检方式 |
|:---:|:---|:---|:---|
| 1 | **菜单脚本渲染** | 调用 `vibe_render_menu.py --json` | 输出含 `"menu":` ✘手动构造 |
| 2 | **阶段收尾四步** | 产出检测 → 放行确认 → Git 提交 → 刷新菜单 | 用户看到更新后菜单 |
| 3 | **用户决策点等待** | 菜单展示、参数缺失、确认点必须等待用户输入 | 未自动继续执行 |
| 4 | **菜单渲染前自检** | 渲染前检查状态文件、Git 同步 | 自检清单无 ❌ |
| 5 | **状态文件路径** | `features/<name>/docs/`，不是 `features/<name>/` | 路径含 `/docs/` ✘根目录 |
| 6 | **会话内不重复选需求** | 已选需求后，菜单导航直接返回当前菜单 | 未重新显示需求列表 |
| 7 | **已放行阶段详情** | 选择 `approved` 阶段时用 `--mode phase-detail` | 显示详情面板 |
| 8 | **Hub 禁止执行 S 阶段** | S01-S07 必须在服务目录执行 | ✘在Hub执行S01 |
| 9 | **阶段执行走 vibe_execute** | 必须调用 vibe_execute 脚本执行阶段 | 看到 execute 输出 |
| 10 | **阶段执行必读 phases.md** | 执行前 `read_file` 加载 `vibe_flow_phases.md` | 上下文包含该文件 |
| 11 | **控制权交还** | Flow 模式下忽略"阶段衔接提示"，产出后进入放行流程 | 未输出"建议进入下一阶段" |

> 💡 **脚本自动保证**（无需记忆）：模式显示、耗时计算、P06 解锁判断、Banner 格式、S 阶段入口过滤、禁止编造预计耗时

## 📋 执行流程（按步骤执行）

### 步骤一：Banner 展示

```bash
python .vibe/tools/scripts/vibe_flow/vibe_render_menu.py --mode banner
```

**AI 必须**：
1. 执行脚本（Blocking=true）
2. 将脚本输出**放入代码块**展示给用户
3. 确认版本号正确

---

### 步骤二：版本检测

> 🚨 **Banner 后、一键启动前执行**，如提示升级且用户选择退出，需升级后重试

```bash
python .vibe/tools/scripts/vibe_flow/vibe_check_upgrade.py
```

**脚本自动完成**：
- ✅ 工作区 vs 目标版本检测（需求池/服务）
- ✅ 24 小时静默机制（跳过后 24h 内不再提醒）

**退出逻辑**：
- 若提示升级且用户选择退出 → 终止流程，需升级后重新启动 `@vaf_starter`
- 若用户选择跳过或无需升级 → 继续执行步骤三

---

### 步骤三：阶段选择

```bash
python .vibe/tools/scripts/vibe_flow/vibe_startup.py --json
```

**脚本自动完成**：
- ✅ 目录校验（检测 VAF 源码仓）
- ✅ Git 同步（自动 pull）
- ✅ 工作区检测
- ✅ 需求检测（单需求自动选择，多需求交互选择）
- ✅ 菜单渲染

**AI 必须**：
1. 解析 JSON 中的 `menu` 字段
2. 将菜单**放入代码块**展示给用户
3. **识别可选阶段**：只有 ✅/🟠/👉 状态可选，🔒 锁定阶段不可执行
4. **等待用户输入**，提示时只列出可选编号
5. **无执行确认**：用户选择后直接执行，无需 `[y/n]`

> ⚠️ **锁定阶段处理**：用户选择锁定阶段时，提示解锁条件，不执行

**🚨 阻断点处理**：
| 脚本输出 | AI 行为 |
|:---|:---|
| `⚠️ 当前目录指向 VAF 源码仓` | 展示警告，等待用户切换目录 |
| `❌ 未检测到工作区配置` | 展示初始化命令，等待用户执行 |
| `status: "select_required"` | 展示需求列表，等待用户选择 |
| 菜单 JSON | 解析 `menu` 字段，代码块展示 |

> 🚫 跳过阻断点 = **BLOCKER 级错误**

> **适用场景**: 用户启动 Vibe 流程的统一入口，自动检测进度并引导下一步
>
